Today we would like to announce the release of RESTEasy link:/downloads#800alpha1[8.0.0.Alpha1],
link:/downloads#706final[7.0.6.Final] and link:/downloads#6220final[6.2.20.Final]. 7.0.6.Final and 6.2.20.Final address
a security vulnerability, and we would encourage all users of those streams to upgrade.

We are excited that 8.0.0.Alpha1 is the first release of RESTEasy 8.0, which targets
https://jakarta.ee/specifications/restful-ws/5.0/[Jakarta REST 5.0]. Jakarta REST 5.0 is currently at its M1 milestone
and is slated for Jakarta EE 12. Both the specification and this release are early, so expect changes along the way. The
biggest change is the CDI integration in https://redhat.atlassian.net/browse/RESTEASY-3807[RESTEASY-3807]. Jakarta REST
5.0 requires CDI, so resources, providers and `Application` subclasses are now CDI beans, and CDI injects the Jakarta REST
context types. `@Context` is implemented as a CDI qualifier, as proposed for the specification. This release also
requires Java 21 and moves to Jakarta EL 6.0 and Expressly.

https://redhat.atlassian.net/browse/RESTEASY-3823[RESTEASY-3823] is an information disclosure in the default exception
mapper tracked as https://github.com/resteasy/resteasy/security/advisories/GHSA-j2p5-4ph4-86cx[CVE-2026-120971] (CVSS
5.3, Medium). For an unhandled exception, the mapper wrote the exception's message to the body of the 500 response, which
could expose internal details to clients. The vulnerability affects 6.2.19.Final and lower, and 7.0.5.Final and lower. It
applies when an exception other than a `WebApplicationException` reaches the default exception mapper, meaning no
application `ExceptionMapper` covers the exception type and `dev.resteasy.exception.mapper` is not set to `false`.

The fix changes behavior for everyone, not only for those who were exposed. Unhandled exceptions now return a 500 with
no entity, so clients which read the message from the response body will get an empty body. Applications which want to
return a message need to register their own `ExceptionMapper`.

Both 7.0.6.Final and 6.2.20.Final also remove the enhanced CDI integration added by
https://redhat.atlassian.net/browse/RESTEASY-3755[RESTEASY-3755], in
https://redhat.atlassian.net/browse/RESTEASY-3822[RESTEASY-3822]. This removes CDI injection of `+@*Param+` values and of
`@Context` members through CDI, along with the `dev.resteasy.cdi.enhanced.enabled` property. It was added in error in
7.0.3.Final and 6.2.17.Final, and it caused issues which can only be fixed by the new integration in RESTEasy 8.0. On 7.0
it was enabled by default, while on 6.2 only applications which set the property to `true` are affected.

== 8.0.0.Alpha1

RESTEasy 8.0.0.Alpha1 is an early https://jakarta.ee/specifications/restful-ws/5.0/[Jakarta REST 5.0] implementation,
built against the `5.0.0-M1` API. This release includes the Jakarta REST 5.0 CDI integration, implementations of the new
Jakarta REST 5.0 API methods such as `getHeaderString(String, String)` and the Java 21 baseline.

=== Enhancement

* https://redhat.atlassian.net/browse/RESTEASY-3313[RESTEASY-3313] ContextualExecutor worker submitting to itself still invokes classpath scan
* https://redhat.atlassian.net/browse/RESTEASY-3807[RESTEASY-3807] Jakarta REST 5.0 CDI Integration
* https://redhat.atlassian.net/browse/RESTEASY-3829[RESTEASY-3829] Implement getHeaderString(String, String) for Jakarta REST 5.0
